# PatchProof Benchmark Specification

The suite contains twelve small, isolated web-service repair tasks. Hidden tests measure the issue contract and guard meaningful regressions; they do not prescribe an implementation.

| Case | Framework | Bug category | Intended acceptance behavior | Why realistic | Hidden measurements | Challenging |
|---|---|---|---|---|---|---|
| PP-01 | FastAPI | Input validation | Reject quantities below one with 422 while preserving valid 201 responses. | Boundary constraints are often omitted from request models. | Zero, negative, and minimum-valid quantities plus success schema. | No |
| PP-02 | FastAPI | Pagination boundary | Treat offsets as zero-based and return adjacent pages without gaps or overlaps. | Slice/index translations commonly introduce one-item boundary errors. | First page, later offset, page continuity, and default listing contract. | No |
| PP-03 | Flask | HTTP missing-resource semantics | Return a JSON 404 for unknown books while preserving existing resource responses. | Optional datastore lookups are easily serialized as null under a 200 response. | Missing ID status/body, existing contract, and framework routing edge. | No |
| PP-04 | Flask | JSON request validation | Return the API's JSON 400 response for missing, malformed, or non-object JSON. | Content parsing failures and unexpected JSON shapes cross framework/application boundaries. | Three invalid-body forms and valid 201 response contract. | No |
| PP-05 | FastAPI | Async integration | Resolve the async inventory result in detailed responses while preserving summaries and 404s. | Async service functions are frequently introduced behind an existing endpoint branch. | True/false resolved results, summary schema, and missing product behavior. | No |
| PP-06 | FastAPI | Exception mapping | Map the domain not-found error to the documented 404 without masking unexpected failures. | Layered services need deliberate translation from domain to transport errors. | Missing and existing users plus unrelated server exception behavior. | No |
| PP-07 | FastAPI | Cross-file normalization | Apply case/whitespace email identity consistently to storage, lookup, and duplicates. | Canonicalization often drifts across controller, service, and repository boundaries. | Variant lookup, normalized duplicate conflict, creation contract, and unknown lookup. | No |
| PP-08 | Flask | Cache key correctness | Isolate cached search results by query parameters while retaining stable responses. | Path-only cache keys are a common mistake in HTTP caching wrappers. | Sequential distinct queries in one process, repeat stability, and empty-query contract. | No |
| PP-09 | FastAPI | Error handling regression trap | Return 409 for reserved seats without changing successful 201 status or nested JSON schema. | Fixes to endpoint status handling can accidentally alter all responses. | Failure status/body, exact success status/schema, and repeated reservation behavior. | No |
| PP-10 | FastAPI | Environment configuration typing | Interpret configured timeout text numerically and retain the numeric default. | Environment variables are strings even when downstream operations require numbers. | Env-provided decimal semantics, default/boundary behavior, fractional input, and invalid config. | No |
| PP-11 | Flask | Atomic state mutation | Validate an update before committing any fields; preserve valid updates and 404 behavior. | In-memory and persistence updates can leak partial writes when validation is interleaved. | Post-error stored state, multi-field and single-field success, and missing resource. | No |
| PP-12 | FastAPI | Idempotency and retry | Reuse the original persisted job for the same key, including after an interrupted response. | Client retries after uncertain persistence are routine in distributed systems. | Timeout retry, same/different keys, stored cardinality, and normal creation. | Yes |
